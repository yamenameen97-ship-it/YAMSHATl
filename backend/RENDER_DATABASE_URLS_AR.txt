🔬 السبب الجذري للخطأ في v89.49
═══════════════════════════════════════════════════════════════

الخطأ الظاهر في لوجز Render:

    psycopg2.OperationalError:
      could not translate host name "dpg-d96nf4uq1p3s73d2m95g-a" to address:
      Name or service not known

    ERROR:app.services.background_tasks:Shop reservations sweep error:
      (psycopg2.OperationalError) could not translate host name "dpg-..." to address

السبب: رابط Render Internal (dpg-xxx-a بدون domain) يعمل فقط داخل شبكة
Render الخاصة. عندما تفشل شبكة DNS الداخلية لأي سبب (cold start،
منطقة مختلفة بين الخدمة والقاعدة، خيط خلفية يفتح اتصالاً أثناء انقطاع
مؤقّت)، لا يستطيع psycopg2 حلّ الاسم، فيفشل الاتصال ويظهر 500 Internal
Server Error عند تسجيل الدخول.

✅ ما تم إصلاحه في v89.50 (DNS FALLBACK ROOT FIX)
═══════════════════════════════════════════════════════════════

1) ملف جديد: app/db/url_resolver.py
   - resolve_database_url(): يبني قائمة مرشحين (Internal + External +
     مشتقات لكل المناطق) ويجرّب كل واحد بـ DNS + TCP قبل تسليمه لـ
     SQLAlchemy.
   - Idempotent: بعد أول نجاح يخزن النتيجة ولا يعيد الفحص.
   - Thread-safe: يستخدم قفلاً واحداً لتفادي إعادة الفحص من عدة خيوط.

2) app/db/session.py:
   - أصبح يستدعي resolve_database_url() بدلاً من قراءة DATABASE_URL
     مباشرة، مما يوفر Internal→External Fallback تلقائياً لكل شيء
     يستخدم SessionLocal (الويب + Celery + خيط الخلفية).

3) alembic/env.py:
   - يستخدم نفس المحلّل — هجرات Alembic تعمل من أي بيئة.

4) .env:
   - أُضيف DATABASE_URL_EXTERNAL كـ fallback صريح للسرعة القصوى.

🚀 خطوات النشر
═══════════════════════════════════════════════════════════════

1) ارفع محتوى هذا الأرشيف إلى مستودع Git.
2) في Render → خدمة yamshat-1ya4 → Environment:
   - DATABASE_URL          = رابط Internal الجديد (من لوحة Render).
   - DATABASE_URL_EXTERNAL = رابط External الجديد (من لوحة Render).
3) Manual Deploy → Deploy latest commit.
4) راقب اللوجز — يجب أن ترى:

   [db-resolver] probing candidate #1/6: postgresql://...@dpg-xxx-a/yamshatdt
   [db-resolver]   ↳ OK ✅ selected: ...       ← أو
   [db-resolver]   ↳ DNS FAIL — skipping
   [db-resolver] probing candidate #2/6: ...oregon-postgres.render.com...
   [db-resolver]   ↳ OK ✅ selected: ...
   Database engine will connect to: postgresql://...@... (masked)
   🚀 Yamshat backend started
   🗄️  Database initialization completed (force=True)
   ✅ All N routers mounted successfully

5) جرّب /api/health و /api/warmup → يجب أن يرجع 200 OK.
6) سجّل الدخول بحساب المسؤول — يجب أن يعمل فوراً.
